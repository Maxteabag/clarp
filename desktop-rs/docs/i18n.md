# Languages in the Rust desktop

The desktop ships in English (the source), Norsk bokmål (`nb`), simplified
Chinese (`zh-Hans`), Hindi (`hi`), Spanish (`es`) and French (`fr`). The pattern
is shared with the other Clarp apps; this page is the desktop's part of it.

## One catalog for Slint and Rust

English is written in the source. The translations live in
`desktop-rs/i18n/<lang>/LC_MESSAGES/clarp-slint.po`, one gettext file per
language. Slint bundles those files into its generated code
(`with_bundled_translations` in `slint-app/build.rs`), and `clarp-core`'s build
script turns the same files into the table Rust's `tr!` reads. So each language
has one file, `.slint` and Rust use the same syntax, and nothing is looked up
on disk at run time. Strings are keyed by their English alone (no default
context), so a text shared by a `.slint` file and Rust is translated once.

Why not a keyed table: the English is the key on iOS too, translators see the
real sentence, and Slint's own `@tr` works this way. Why not gettext at run
time: the binary is installed as one file, and bundled catalogs need no
locale setup on the machine.

## Adding a string

Every string carries a note for translators, a `// i18n:` line right above it
(or at the end of its line): where it appears (the screen and the element:
button, title, row label, accessibility label, toast, placeholder), what it
does, and whether it is a verb or a noun when the English could be either
("Match", "Archive", "Copy", "Open", "Done"). Machine translation without one
put an infinitive on a Norwegian Send button and turned "next match" into a
football match. `tools/i18n-export` refuses a string without a note.

Strings are grouped by screen so translators and reviewers work a screen at a
time. The screen is the nearest `// i18n-screen: NAME` line above the string in
its file, else the file's name: `settings.slint` and `settings_view.rs` are
"settings", everything under `catalogue/` is "settings". Name a screen in the
file when its name does not say it (`// i18n-screen: dates`).

Plain text, in a `.slint` file or in Rust:

```slint
// i18n: Settings page, title at the top (noun)
Text { text: @tr("Settings"); }
```
```rust
// i18n: Settings > Appearance, row label (noun): the setting that picks the app's language
let label = clarp_core::tr!("Language");
```

A placeholder: `{}` takes the next argument, `{0}` `{1}` a numbered one (use
those when a language may reorder them):

```rust
// i18n: connection page, status line under the Host's address; {} is the Host's name
tr!("Connected to {}", host_name)
```

A plural: one form for one, the other for the rest; `{n}` is the count. Each
language gets the forms it needs (Chinese one, the others two):

```slint
// i18n: composer, label beside the attachments; {n} is how many files are attached
Text { text: @tr("{n} file" | "{n} files" % root.count); }
```

An accessibility label is text like any other:

```slint
// i18n: composer, accessibility label of the send button (an action: send the typed message)
Rectangle { accessible-role: button; accessible-label: @tr("Send this message"); }
```

A date, time, number or relative time never builds words by hand; use
`clarp_core::i18n::format` with the language in use:

```rust
use clarp_core::i18n::{self, format};
let stamp = format::day_month(i18n::current(), day);       // "Nov 26", "26. nov.", "11月26日"
let clock = format::time(i18n::current(), at, format::Clock::H24);
let ago = format::relative(i18n::current(), -300);         // "5 minutes ago"
let count = format::number(i18n::current(), 1_234_567);    // "1,234,567", "12,34,567"
let heading = format::relative_day(i18n::current(), day, today); // "Today", "I går"
```

When the same English means two things in two places, give each a context so
each gets its own translation:

```rust
// i18n: file row, button (verb): opens the file
tr!("verb" => "Open")
```

Buttons and actions use each language's own command form (imperative in
Norwegian and Spanish, infinitive in French), following glossary.json.

Do not translate Clarp, Host (the product noun), agent and model names, file
names, code, commands or the user's own text. Never hand-write a translation
into code or branch on the language.

Text kept in a `const` or static table (the Ctrl+K commands, the settings,
the preferences, the vim keys) cannot call `tr!`. Mark it with
`crate::catalogue::en::tr!("English")` (in `clarp-core`'s prefs, its own
`en::tr!`): the exporter reads it like `tr!`, note included, and the table
keeps the English, so ids, tests and search keep working in English. Draw it
with `crate::catalogue::local(text)` (`Entry::label_text`,
`prefs::translated`). A marked text has no context; when it needs one, make
the text where it is drawn with `tr!` instead. Search matches both the
translated words and the English ones (`catalogue::entry_score`).

Rust text must be made where the view is drawn (a `refresh`, `show` or row
builder), not kept from start-up: a language change redraws those views, while
text cached at start would stay in the old language until a restart.

## The language setting

Settings → Appearance → Language. "System" (first, the default) follows the
computer's preferred languages: `LANGUAGE`, `LC_ALL`, `LC_MESSAGES` and `LANG`
on Linux, the system list on macOS. `nb`, `nn` and `no` read as Norsk bokmål;
`zh`, `zh-Hans`, `zh-CN` and `zh-SG` as simplified Chinese; anything else not
shipped is skipped, and English is the last resort. The other options are the
languages by their own names. The choice is kept per device under
`appearance/language` in the app's settings file, and applies at once: Slint
text through `slint::select_bundled_translation`, Rust text through
`clarp_core::i18n::current()`, with the open views drawn again
(`slint-app/src/language.rs`). `--check language` drives it headless.

The formatters use ICU4X's compiled CLDR data. Slint already carries ICU's
number and plural data; the date and time data adds about 1.3 MB to the
binary. Relative times are catalog plurals, because ICU's relative-time
formatter is experimental and pins an older ICU that would ship twice.

## Screenshots in a language

Translations are reviewed on screenshots of the real screens, next to the
English ones. One command shoots the main screens (chat, settings, command
palette, keys, updates, teams) in one language, headless against the fake Host:

```sh
desktop-rs/slint-app/tests/screens.sh nb /path/to/out      # out/chat-nb.png, out/settings-nb.png, ...
```

It needs a debug build (`target/debug/clarp-slint`), so run it where the
desktop builds: in CI, `gh workflow run desktop-checks.yml -R Maxteabag/clarp
--ref <branch> -f checks="screens-en screens-nb screens-zh-Hans screens-hi"`
and download the `checks` artifact. One screen alone:
`CLARP_LANGUAGE=hi CLARP_SHOT_COMMAND=settings slint-app/tests/shot.sh out.png`
(`CLARP_LANGUAGE` overrides the setting for that run; `CLARP_SHOT_COMMAND` is
any command name `commands::run` takes). `--check language` shoots the
Language row and its picker in English, Norwegian, Chinese and Hindi.
Chinese and Hindi need fonts that cover them (CI installs `fonts-noto-cjk` and
`fonts-noto-core`).

## Exporting and importing

```sh
desktop-rs/tools/i18n-export /path/to/dir/        # writes en.jsonl
desktop-rs/tools/i18n-import /path/to/nb.jsonl    # writes i18n/nb/LC_MESSAGES/clarp-slint.po
```

The export reads every `@tr` and `tr!` in `slint-app/ui`, `slint-app/src`,
`core`, `engine` and `net`, and writes one JSON line per string, in source
order: `{"key", "en", "comment", "screen", "placeholders", "plural"}`. The key is the
English, or `context` + U+0004 + English. `comment` is the `// i18n:` note
(and the context), `screen` its screen, `plural` `{"one", "other"}` or null.

The import takes lines `{"key", "text"}` or `{"key", "plural": {"one",
"other"}}` (Chinese needs only `other`), keeps the translations a line does not
replace, refuses a line whose placeholders differ from the English, reports
keys the source no longer has (`--prune` drops them), and writes the file
sorted, so the same input gives the same bytes. Both exit 1 and list what they
refused.
