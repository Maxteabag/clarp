# Differences from the Python Host, on purpose

The Rust Host joins the fleet on the contract the apps already speak. Where it differs from the
Python Host in something a client can see, the difference is in this file with its reason, or it
is a bug. The conformance run (`../conformance`) finds the differences; this file explains the
ones that stay.

## Features that are not there yet

The Rust Host leaves a feature it does not have out of `capabilities.features`, which is how an
app learns not to expect it. What belongs to such a feature is left out of both sides before the
conformance run compares them (`NOT_YET` in `conformance/conform.py`).

| Feature | What is absent | Planned |
|---|---|---|
| `send_delivery_state` | `/log`: `delivery_scope`, `delivery_stop_generation`, and `delivery` on a user row; the event `delivery-updated` | Stage 3 |

The Rust Host lists a feature when everything the feature names is built and held to the Python
Host (`FEATURES` in `crates/clarp-host/src/edge.rs`, each with the contract number that
introduced it, as the Python Host's `FEATURE_CONTRACTS` has it). On 16 Nov 2026 these are:
`pairing`, `turn_queue_resume`, `log_turn_summary`, `background_jobs`, `background_job_cancel_generation`,
`durable_task_goals`, `artifacts`, `flat_artifact_responses`, `artifact_summary_v1`,
`artifact_pins`, `decision_lifecycle`, `text_input_requests`, `push_grants`, `push_unregister`,
`desktop_send_quiet_push`, `snapshot_without_archived`, `helper_agents`, `media`, `html_reports`,
`html_report_revisions`, `html_form_network`, `attention_index`, `group_calls`, `agent_rings`, `heartbeat`, and `live_activity_push` on a Host that has a relay and an account of its own there. Everything else in the Python Host's list is absent, also where a part
of it is built (`goal_updater`: a criterion can be set aside, the Goal keeper is not there).

Parts of the contract that no feature stands for, which the Rust Host sends empty for now
(`NOT_BUILT` in `conformance/conform.py`):

| Part | What is empty | Planned |
|---|---|---|
| The vocabulary an engine is asked to listen for | `vocab_run_id` in the answer to `POST /transcribe`: this Host asks an engine to listen for what its agents are called and keeps no runs of a vocabulary | With the vocabulary |
| The explaining of a tool's use | `tool_explanations` in the snapshot and in `GET /live`: off here, where nothing explains. What the setting's own route answers is compared | With the janitor that explains |
| The probes of the Python Host | `delivery_admission` in `GET /status`: the budgets, the gate and the counts of the Python Host's own way of telling whether a turn's process is still its own | Never: this Host has no such machinery, and no client reads the block |

The lists an app's screens are made of, for what the Rust Host keeps nothing of yet (`NOT_KEPT` in
`conformance/conform.py`). An app asks for them of every Host it is paired with, whatever the Host
says it has, so each is answered as the Python Host answers a list, and empty: an app shows nothing
there, where a route that is not there would be an error on its screen. The run compares the status
and every field with its kind.

| Route | What the Python Host has there | What the Rust Host answers | Planned |
|---|---|---|---|
| `GET /janitors` | its seven janitors, their templates, triggers and providers | no janitors, `runtime_available: false` | When janitors are built |
| `GET /transcription-capabilities`, `GET /transcription-providers` | the engines that listen there, the providers and their models | the engines that listen here: this Host's own Whisper, and each provider the owner's file has a key or a project for | Never the same list: each Host says what it listens with |
| `GET /agent-model-options` | every backend with its models, what each supports and how it is signed in | no backends listed. An agent's model is set by name (`POST /agent-llm`) | The catalogue of models |

## Screens of what this Host has not

The phone app asks a Host about fourteen features and calls everything else when its user opens the
screen (counted in its source on 16 Nov 2026: 149 paths, 83 of them not on this Host that morning).
Where this Host has nothing of a kind, the reading is answered in the Python Host's fields with what
is true here, and every change is refused, 501, as not built (`crates/clarp-host/src/screens.rs`;
the Python Host's answers were written down from a fresh one by the conformance workflow). The
scenario `app-screens` compares the readings; four of them as their fields alone, because the Python
Host's first day says there what this Host must not say of itself.

| What an app reads | On this Host | A change |
|---|---|---|
| Whether an agent dreams (`dreaming_enabled` on its row) | off for every agent | turning it off is done (it is off); turning it on is refused (`POST /agent-dreaming`) |
| The goal an agent works toward in the old way (`GET /agent-goal`), a goal's ledger (`GET /goal-ledger`) | none; no events. An agent's goals are its plans here (`GET /task-plans`) | refused |
| Whether a picture could be made (`GET /agent-portrait-generation`), how pictures are set (`GET /avatar-settings`) | not available, and the reason says that it is not built; no pictures by model | refused |
| Judgments, diagnostics, the janitors' policy (`GET /judgments/settings`, `/diagnostics/settings`, `/janitor-policy`) | off, as on the Python Host's first day | refused |
| One janitor and its runs (`GET /janitors/<id>`, `/janitors/<id>/runs`): the desk asks for the janitor that switches account seats | none: answered as the Python Host answers for one it has not (404, `Agent not found`) | refused |
| The account seats of the machine (`GET /hotseat/status`, `GET /hotseat/desk`) | what the Python Host says before anything was read of them: no accounts, the switcher off, nothing installed; and when it said so. This Host reads no seat | switching and resuming (`POST /hotseat/switch`, `/hotseat/resume`) are refused: this Host changes no login |
| Cartesia's old picker (`GET /cartesia-voices`) | none listed. The catalogue of voices (`GET /voice-catalog`) has Cartesia's voices | none |
| Podcasts (`GET /podcast-history`, `/podcast-history/sources`) | none | none |
| The vocabulary (`GET /vocab/packs`, `/vocab/terms`, `/vocab/profiles`, `/vocab/profile`, `/vocab/assignments`, `/vocab/runs`) | no packs, terms, profiles, assignments or runs | refused. `/vocab/budgets` is not answered yet |
| A ring held as a live voice call, a ring that listens first, a phone's own switch for rings (`/calls/ring/live`, `/calls/ring/live/close`, `/calls/ring/live/fallback`, `/calls/live`, `/calls/ring/opening`, `/calls/ring/device`) | nothing: these have no screen that is read | refused in words (501). Calls and the ring whose opening line is said are built: see below |
| The Oracle (`GET /oracle/status`, `/oracle/contact`, `/oracle/delegations`, `/oracle/calls/status`) | not available, and nothing it could do is claimed; nobody is put through; nothing was handed on | refused |
| The tools' logins (`GET /backend-auth`) | whether each tool this Host runs (Claude Code, Codex) is installed and has a login, read off the file the tool keeps it in; a login that is there is told as not verified, because this Host asks no provider; no account's name | signing in or out from an app is refused: it is done with the tool itself |
| How much of an account is used (`GET /backend-usage`) | unknown for each tool: this Host asks no provider and keeps no account of what its turns cost | none |
| The Host's software (`GET /server-update`) | who it is, that nobody looked for a newer one, and that it is not updated from an app | refused: whoever installed it updates it with the installer |
| The skills kept installed for the tools (`GET /managed-skills`) | none: this Host manages no skills | refused |
| The sessions a tool had in a directory (`GET /past-sessions`) | none offered | taking one up or forking one when an agent is made is refused (`resume_unsupported`) |

Refused in words, 501, as not built: compacting a conversation from an app (`POST /compact`), a
tool's own servers (`POST /agent-mcp`), nudging a team (`POST /team-nudging`), signing a harness in to
a provider of models (`/harness-providers`: none is listed).

Not answered yet, each "no such route": how an engine is told what to listen for
(`/transcription-guidance`), the orchestrator's settings, the budgets of the vocabulary, dreaming's
settings and runs (an app asks for them only of a Host that lists `dreaming`), the Oracle's voice.

## Compared as what a client may rely on

| What | The Python Host | The Rust Host | Why it is compared this way |
|---|---|---|---|
| Revisions | a counter that grows with every write of a row, one for the whole Host | the agent's own log position times 2^20, with room for a reply that grows | The contract promises that a client which holds a cursor is given what changed since, not numbers. The run compares a head as its place among the cursors the capture handed out for that conversation, and a row's revision as how many of those cursors it is newer than. How two rows that changed between the same two cursors stand to each other, no client can tell, and the Python Host writes them in either order (defects R8, R16) |
| The Host's version in `server-version`, and `clarp_version` in `GET /server-info` | the newest change time of its static files; the version of the Python package | its own version | Each Host's own. The run compares that there is one |
| The id of a row the agent wrote | `live-` and a hash of the agent, the session, the trace and the tool's message id | `r-` and the tool's message id, or the id of the message it answers and a number | An id is the Host's own choice. The run compares that the same row has the same id wherever it is named. The prefix is different on purpose: in the apps `live-` marks a row that has no fixed place in the history yet (the iOS app does not page back from one, `HistoryCursorPolicy`). A row of the Rust Host is stored under one id from its first word and has a place from then on |
| The id of something an agent made or asked (`artifact-...`, `decision-...`), in a path a client calls and in what the agent is told and says back | random | random | The run gives each id one name wherever it is written, also where a preview cut it short, and compares that. Only ids the Host gave out under an id's own key in the same capture: other hex in a text is content |
| The id of a file an agent published (`asset_...`), under its own key, in `url`, `uri` and `markdown`, and in the path it is fetched by | `asset_` and 24 random signs | `asset_` and 24 random signs | An id is random on both. It is named in the order a client first learns of it, wherever it is written: what a client relies on is that the id it was given fetches the file |
| When an artifact was pinned, put away, thrown away, and when a request was answered | a reading of the clock | a reading of the clock | The run compares that there is one, and where there is none |
| A queue's revision | counted per change of the queue | the same changes, counted the same: a message that was left for later counts as joining and leaving, also when nothing is in its way | Compared as the number it is |
| The start of the turn that runs, `turn_started_at` in the snapshot | the first busy state the agent entered after its last turn ended | the moment the turn that runs was taken up; at rest 0 | A reading of a clock, which an app counts the running turn from (issue 354). The run compares which turn it is the start of, and which message the client had last sent when it began. `live_activity.turn_started_ms` is the same moment here. On the Python Host it is the start of the newest message's turn and begins again when more is sent to an agent that works (397 of 2,899 working stretches on elitebook in four days, found by the review of PR 357), so the apps count from `turn_started_at` only |

## Differences that are registered one by one

Each has its id in `../conformance/intended.txt`. The id is a hash of the place and both values:
it covers that exact difference and nothing else.

| What | The Python Host | The Rust Host | Why |
|---|---|---|---|
| A plain send that has to wait | changes the queue and announces nothing (defect R5) | announces it with `queue-updated`, like a send with `queue_if_busy` | Every device shows the same queue, not only the one that sent |
| The preview of a notification for a spoken reply | shows an emotion tag the engine acts out, `[sigh]` (defect R10) | does not | A notification shows the reply as every other place shows it |
| What the conversation shows of a turn that follows a settled one | only the rows written while the turn ran: what the agent said, with `phase: null`, without the cards of its tools and without the messages that only call tools (defect R6). The first turn of a conversation has all of it | every turn the same: a row for each message of the agent, a card for each tool it calls, `commentary` for what was said before tool work and `final` for what was said after it | What a turn did is shown whichever turn it was. The scenario `tool-turns` has two turns for this: the first is the same on both Hosts in every field |
| `last_completed_message` after a later turn of an agent: one that had waited in the queue, or a plain one that was not its first | the user's message, though the agent has answered it (defect R12) | the agent's answer | A list of chats shows what the agent last said, whichever way the turn began |
| `model` in an agent's row after a turn that completed | empty after some turns (defect R13) | the model that answered | An app shows which model an agent runs on; a turn that completed has said it |
| `pinned` in the answer to the discard of a pinned artifact | `true`, beside `pinned_at: null` (defect R15) | `false` | A discard unpins. The answer says what is now true |
| A reply, to a client that catches up by revision | given again after the next message arrived: the Host wrote it a second time (defect R16) | given once | A row that did not change is not sent again |
| `live_activity` in an agent's row after its first turn | missing until the next turn, in some runs (defect R17) | there: at rest, since the turn's end | An app's line for an agent says what the agent last did, whichever turn that was |
| What the older channel is told of a streamed turn (`agent-state`, `agent-activity`) | each phase the stream goes through, as it is read line by line: that the model's thinking has begun (`detail.phase: thinking`, and the activity once more), then its answer (`phase: responding`) | the state the agent is in when what there is to read has been read; an agent that begins to stream its answer is told as answering (`phase: responding`), and that its thinking streams is not told a second time | An event says what is, not what was a moment ago: a turn whose whole stream arrives at once is told as it ends. The corpus's stand-in prints a turn in one breath, so the scenario `live-items` shows four events less; a real turn is told as answering when its answer begins. The live items carry every step on both Hosts |
| What the conversation and the live view say of a conversation's first streamed turn | in some recordings: the answer's live item and its notification name a row the conversation does not have, and no row carries the turn's summary (defect R19) | the item and the notification name the answer's row, and that row carries the turn's summary | The row an answer is written into while it grows is the row that stays. Registered for `live-items`, for the recordings in which the reference does it; and for `who-is-told`, where a run showed the same in a first turn that is not streamed (the first reply without the turn's summary, its notification naming a row that is not there) |
| What a Host says it listens with (`GET /transcription-capabilities`) | with an engine of its own: which engine hears a clip nobody named one for (`engine`), where a turn of speech ends (`turn_taking`), what could be installed (`catalog`). The reference Host of the suite has a stand-in for an engine and answers with four fields only | always the fields of a Host with an engine of its own | An app reads the same fields from every Host. Registered for the two scenarios that ask |
| How a child a fork makes starts (`fork` in the child's row of the answer to `POST /agents/<session>/fork`) | `native` where the tool can copy a conversation itself and the child runs on its maker's tool (Claude Code: the session's file under a new id; Codex: the thread forked), `seed` otherwise: the most recent part of the conversation as words at the head of the child's first message | always `seed` | A tool's own copy of a conversation is not made on this Host yet. What a child is given as words is the same on both: at most 60,000 signs, counted from the newest thing said, each thing said cut at 4,000 |
| What a tool that died left on stderr, as the state of the failed turn gives it (`detail.error`) | as the tool wrote it, with the end of its last line | the same words without the line's end | The words are what failed, the line's end is how a terminal was told. `detail.provider_message` and the row under the message carry them without it on both Hosts |

## Differences the conformance corpus does not reach

| What | The Python Host | The Rust Host | Why |
|---|---|---|---|
| A plain send to a busy agent from something that is not a person | ends the running turn ("legacy other origins preempt", defect R7) | waits its turn | No automation ends a turn a person may be waiting for |
| Pushes to phones | on by default, through the developer's relay | off until the Host is given a relay (`--push-relay`); `tools/install-host` names it | A Host that is started bare speaks to nobody outside. Tests and disposable Hosts never reach a real relay |
| A paired device with limited scope registers a push token | registers a row nobody owns | refused, 403 | A limited device may read and send; it changes nothing on the Host |
| Phones reached through FCM (Android) | pushed to through a Google service account | registered, not pushed to yet | Built when an Android phone is to be reached |
| A push straight to Apple with the Host's own key, Live Activities, the silent push that asks an app to sync, the agent's portrait in a push | there | not there | A Host reaches a phone through the relay: by the phone's grant, or by the Host's credential there. The rest comes with the surfaces it belongs to |
| A message from an agent the Host does not have (an agent of a peer Host) | filed as an agent's, without a sender | filed as an agent's, with the name the sender gave | The reader sees who wrote, and on which Host to answer |
| A send that names its sender and an origin beside it (`user`, `oracle`, `schedule`) | taken as the origin it names (defect R18) | that agent's: `agent` | Who a message is from decides whether the focus moves and whether a Stop holds it. An agent is not a person because it says so |
| A turn whose account is out, on a machine with an account selector | the Host runs the owner's selector: it stops every running turn of that tool, lets the selector put another login in place, and resumes them all | never changes a login and stops no turn: the turn waits and is taken up when the login has changed, or ends after half an hour (`--accounts follow`) | Two Hosts on one machine share the tools' logins. The one that has the selector changes them; the other follows. A selector of this Host's own comes when a machine has no other Host |
| The hours of the day in which no agent is given a heartbeat, and the heartbeat's settings as an environment gives them (`CLAUDE_PWA_HEARTBEAT_ACTIVE_HOURS`, `..._INTERVAL_SEC`, `..._BACKOFF_CAP_SEC`, `..._DORMANT_AFTER_NOOPS`, `..._QUIET_PERIOD_SEC`) | read when the Host starts | not read: the settings are what the apps set (`POST /heartbeat/settings`), and an agent is left alone for its interval after somebody spoke with it | The rule for the hours is in the kernel. The owner's Host on elitebook sets none of the variables (looked on 16 Nov 2026) |
| Changing the words of a message that waits its turn in the conversation: one that was said while a turn ran and was not left for later (`PUT /turn-queue/<id>`) | does not arise: a message waits in the queue, outside the conversation, until its turn starts | refused, 409, `message is already in the conversation` | Where a message waits is this Host's own (a plain message is said at once). What was said stands; what was left for later is changed on both Hosts |
| A waiting message sent by hand while a turn of its agent runs (`POST /turn-queue/<id>/send`) | refused, 409 `agent is still working`; the count of the queue's changes (`revision`) moves by two with the refusal: the message is claimed and let go again | refused in the same words; the count does not move | Nothing changed. Seen in conformance run 43965744063; not asked in a scenario, because every number after it would differ. This Host's own test holds that the count stays |
| A message that was taken back out of the queue, sent again under the same id | taken as a new message | the same message, which was taken back: it does not run | An app mints an id once for each message. Not carried further |
| What a heartbeat's turn counts as when the agent says more than one thing in it | activity as soon as one of its messages is more than an excused remark, also when its answer is that nothing is to be done (defect R28) | what its last answer says: nothing found when that is the token, activity when it says something else | An agent whose tool narrates would otherwise never be asked less often and never go dormant. Reported; counted on the owner's Host (see R28) |
| An agent a keeper serves (a janitor that keeps heartbeats for the agents in its scope) | not given the fixed heartbeat, and its profile shows no next one | given the heartbeat like every agent that asked | Janitors are not built |
| What wakes an agent whose heartbeat has backed off or gone dormant | its user speaking to it, its team moving, a promotion in a leader's memory | its user speaking to it | Teams and leaders are not built |
| The model an agent's row shows after a turn that was stopped | the model of the last answer in the tool's transcript | the model of the last completed turn | The same thing, read from what the Host has. A turn that was cut off may not have said its model yet |
| A model an agent is set to that its tool does not have | refused for Codex when the Host has the list `codex debug models` gave it, and by `clarp-admin model` for every tool, from the catalogue the apps read | taken; the tool says so at the agent's next turn | This Host has no catalogue of models yet. It comes with accounts and usage |
| Two names that differ only in letters that fold to others (`ß` and `ss`) | one name (`str.casefold`) | two names (small letters compared) | Names are compared without their case. The rest of the folding table is not carried for a case no fleet has |
| The words a forked child is given of its maker's conversation | read from the tool's own transcript of it | read from this Host's own record of the conversation: its newest thousand rows; a tool's call is the line this Host words it in for an agent's activity (the command, the file), and a row that came with the agent from another Host is read as that Host served it | This Host keeps the conversation itself and does not read a tool's files. A child of an agent that was moved here starts from what was said before the move too |
| `clarp-admin agent fork --spec -` (the list of children on standard input) | read | refused in words: the list is written to a file and the file is named | A tool of this Host is a pipe to it, and what is piped into the tool is not carried along |
| A fork asked for by a bookkeeping delegate of a goal, or of an agent that descends from one | refused, 409 | not refused | Delegates of a goal's bookkeeping are not built |
| The session name of a new agent | the name asked for when nobody has it, else the agent's name in small letters and four random letters (`maximus-6c37`) | the name asked for when nobody has it, else the agent's name in small letters, with random letters only when that is taken (`maximus`) | A session name is the Host's to choose and a client's to copy. The shorter one is easier to say and to type |
| A helper that answers its maker's request (`clarp-admin reply`) | has reported, and the apps are not told | has reported, and the apps are told to read the list again | Every move of a helper is announced the same way |
| A file an agent publishes, when nobody says for which agent (`POST /media` without `X-Session`), and a gallery asked for without a session | the agent the Host is configured to default to | refused with `session required`; an empty gallery | This Host has no agent it falls back to: every request names its agent |
| A published file that is text, fetched by a client that takes gzip | compressed | as it is | What agents publish is mostly compressed already; a client that asks for gzip is given a file it can read either way |
| What a file with no usable name or extension is called and kept as | by the machine's table of file types (`mimetypes`, which reads `/etc/mime.types` where there is one) | by Python's own built-in table, the part of it a published file can ask for | The same file is read the same on every machine. An image is told by its first bytes on both |
| A hands-free message whose opening word does not end where the agent's name does: it spells the name another way than the agent has it ("Rachél, go" for Rachel), or goes on after the name in a letter, a digit, a mark or a sign that is no punctuation ("Zoëy go", "Zoë1 go", "Zoë+go" for Zoë) | goes to that agent, with the end of that word at the head of what the agent is given ("él go", "ëy go", "ë1 go", "ë+go") | goes to that agent, and the word the name was found in is taken off whole ("go", "go", "go", "+go") | The address is no part of the message. Where the name ends as a word (before a blank, a sign of punctuation, or the end), both Hosts take it off through its end, all its words and however its letters are composed, and a name is not cut out of a longer word ("Anna Mariana please" is "Mariana please" on both): the Python Host since its fixes of R23 and R27. Held by `tests/addressed_vectors.rs`, which names the ten recorded messages that differ |
| Whether a name at the beginning of a hands-free message is an address or only a mention ("did Rachel finish?") | can be asked of a model (the judgment `naming`), off unless the owner turns it on | never asked: the name as written, or one much like it, in the opening words is an address | This Host asks no model anything by itself. As the Python Host with the judgment off, which is how it comes |
| The router that asks a model whom a spoken message is for (`POST /orchestrator/route-delegation`, `GET`/`POST /orchestrator/settings`, `POST /orchestrator/addressing`, `GET /orchestrator/decisions`) | there, off unless the owner turns it on | not there: the app that asks it is answered as by a Host whose router is off (`action: disabled`, nothing sent) and asks its user; its settings read as off, with nothing to run it on; turning it on is refused, 501 | A message that begins with an agent's name finds its agent without a model (`clarp_kernel::addressed`). The router comes with the janitors it is one of |
| The agent a message is for that names none | the one the Host is configured to default to (`default_session`, `claude` unless set) | `claude`, when there is an agent of that name | This Host has no setting for it. A hands-free message stays with the agent that is open before that is asked |
| How exact a place is that a phone says it is at (`POST /location`, `accuracy`), given as a list or an object | 500, `store failed` (a `TypeError` nobody catches as what it is) | 400, `accuracy must be a number` | What an app sent wrongly is the app's to hear, not a failure of the Host. A text that is no number is refused in the Python Host's own words on both |
| How each agent of a call is transcribed (`transcription` in a call's record; the feature `call_transcription_policy`: languages and engines of a call, and a clip that says it is of a call, `X-Clarp-Call-Id`) | there when the owner set a policy for calls, or for a call an agent placed that listens first | not there: a call's record has no `transcription`, which an app reads as unknown and keeps naming its engine; a clip an app sends unmarked, as the apps in reach do, is heard like any other, and one marked as a call's is refused (the row on `X-Clarp-Call-Id`) | Not built; the feature is not advertised |
| A notice of a call for an agent that was never written to | not written: a row needs the session of the agent's tool, and there is none before its first turn | written: the agent finds in its conversation that it was asked into the call | A conversation here is the Host's own from the first row, whoever writes it |
| The clip of a ring's opening line where speech is off (`opening_audio_url`), in the reference's own test harness | there for an agent made through `POST /agents`: the harness's stand-in engine (`FakeTTSEngine`) writes a clip whatever `[tts] provider` says | none: nothing speaks where speech is off | A property of the reference's harness, not of the reference: outside it `TTSEngine.synthesize` refuses with speech off and the ring has no clip, as here. That an opening line is voiced where speech is on is held by this Host's own test with a stand-in engine. Seven places of the scenario `rings`, registered |
| A ring that asks to be held as a live voice call (`conversation_mode: agent_live_v1`, `clarp-admin call ring --oracle`) | checked whole (the event's context, the agent's approved profile), then placed when a phone that can hold one still receives rings, else refused 409 `live_client_required` | refused 409 `live_client_required` after the rules every ring passes (who rings, how often); what the request carries for the live call is not read | No phone holds a live voice call through this Host, and `live_client_required` is the sign a caller rings an ordinary call on. A context that the Python Host would refuse as malformed (400) is answered with that sign here |
| A ring that asks the phone to listen first (`opening_mode: listen_first`) | placed, when the Host can prove which run of itself it is | refused 409, `listen-first opening is unavailable on this Host; ring with opening_mode say` | Not built.
