Clarp's small decisions: today vs Jev

Simulated in Docker on 2026-09-17 07:32 UTC. Every wait and every cost below was measured, not estimated. Clarp is an open-source voice front end for coding agents (github.com/Maxteabag/clarp). Jev is TypeSafe's decision model. Written up by Peter Adams with Claude, which wrote the test situations and the harness.

What this is

Clarp constantly makes small decisions about language: did you just say yes? who are you talking to? was that real speech or noise? Today most of them are made by word lists in the code, and one is made by an OpenAI model.

Jev is a small, fast AI model built for exactly this: you give it the situation and a multiple-choice question, and it answers with the choice and how sure it is. It cannot write text. It only picks.

For each decision Claude wrote realistic situations, decided what should happen, then ran Clarp's real code (the unmodified server modules, mounted read-only into the container) and Jev on the same situations, timing each and counting what each call cost.

Read this before trusting the scores

The test situations were written by hand, and hard ones were included on purpose, so the “today” scores look worse than everyday experience. The scores show what kind of mistakes each approach makes. They do not say how often those mistakes happen in real use. For that, the same harness should be fed real transcripts. Where a Jev question was reworded after seeing a miss, the section says so and the new wording was checked on fresh sentences first.

Waits were measured from a laptop inside Docker; both APIs were called over the public internet. Prices: Jev $0.042/1M input tokens (from TypeSafe's docs). The OpenAI price ($0.75 in / $4.5 out per 1M) is an assumption; token counts are exact, so a corrected price only changes the dollar column.

An agent wants to speak. Did you just say yes?

While you talk with one agent, another (say Rachel) finishes and says “Rachel here, I have an update”. Her real message is held back until you give her the floor. Clarp listens to your next sentence to decide: let her speak, keep her quiet, or it had nothing to do with her.

When it goes wrong: Wrong “yes”: audio you didn't ask for starts playing. Wrong “no”: Rachel's update is silently stuck.

The AI router: what should happen to this sentence?

When no name is heard, Clarp sends your sentence plus every agent's recent conversation to an OpenAI model and asks it to decide: deliver to an agent (which one?), answer a status question, repeat, stop an agent, ignore it, or ask you. This is the only one of these decisions that already costs money today.

When it goes wrong: Wrong agent gets your instruction, passenger chatter is delivered to an agent, or you wait seconds at “AI choosing recipient”.

An agent's turn died. Why?

When Claude Code or Codex ends with an error, Clarp reads the error text to decide what to do: retry silently, tell you, or switch account. The wording changes with every CLI release.

When it goes wrong: A missed “out of usage” means the agent just goes quiet and looks connected. A false one can switch accounts for no reason.

How it was done

A small Python harness runs in a Docker container with the Clarp source mounted read-only. For each situation it calls the real Clarp function (or, for the router, sends Clarp's real prompt to the real OpenAI model) and one Jev request, records the outcome, the wall-clock wait and the token usage, then renders this page. Jev answers are multiple-choice with probabilities; every threshold (“only play audio above 80%”, “ask when no agent is above 60%”) is ordinary code, not part of the model.
