## Input and outcome boundary

The existing plugin proposes controller and gw0..gw7 start/finish records and a
coverage-pid-PID.data file declared by each finish. Neither worker identifiers
nor nine files alone prove nine actual processes. Before aggregation the outer
owner must bind actual boot/PID/start, exact source/config/dependencies/tool and
run identity, full common collection/omissions, controller/worker report
multisets, raw pytest exit and all nine terminals. Existing timing() explicitly
refuses coverage; it must NOT be called with coverage fields stripped to fake a
usable run. Extract/reuse a source-reviewed shared run-validation boundary with
explicit timing versus coverage modes, preserving all timing checks and raw
failures. This is future source, not a second unqualified validator now.

Coverage requires the exact mode, coverage7.17.0 artifact/config/source tree,
branch configuration and recorded process participation. Missing/failed flush,
nonzero raw or qualified exit, conflicting identities, unknown terminal or
outcome mismatch produces PARTIAL, never success from a report percentage.
An empty controller database may be legitimate: distinguish a declared,
readable empty measurement from a missing file. Source/test presence or prior
G1 is never a substitute. Host/runtime/provider children remain UNOBSERVED;
pytest subprocess data cannot certify those children or their lifetimes.

## Explicit data, physical copies, supported API

Freeze an explicit nine-entry artifact list from qualified finish records,
never glob .coverage*, scan directories or rely on similarly named files.
Every input must have a unique role and source artifact identity; physical
original files must be owned, regular, non-symlink, single-link and bound to
exact path/inode/size/SHA256 before and after. Equal byte hashes from different
processes are not duplicate evidence or a reason to omit a role.

Archive and preserve originals; make exclusive distinct-inode private working
copies for the library, with streaming hash/size correspondence and qualified
producer exit/copy boundary. Refuse unresolved WAL/journal/sidecar state; do
not checkpoint, repair or open an original through the coverage API. The
future outer owner supplies exclusive closed-producer custody, not a boolean
claimed by this consumer. All source roots remain immutable and identical to
the measured B source archive. Inventory/copy/API/report/fetch/archive costs
consume the same setup/coverage/final allowances, with no new window or retry.

Proposed combine method is the pinned public CoverageData.read/update API,
with one explicit input object per working copy and an initially absent,
exclusive destination in a fresh owned output directory. Validate every input
before calling update; no directory search, implicit old-data load, context
filter, path remap or hidden omit. Preserve contexts and arcs. A readable
zero-measured-file input remains explicitly listed as empty, not missing; a
nonempty line-only input cannot mix with declared branch data. Record per-input
measured files/contexts/arc mode and union correspondence. Verify each update
was attempted once in the declared order; error/warning/unknown input ends
qualification and preserves partial output. Independent expected union checks
must not use the combined object's own values as their only expectation.

Coverage.combine(strict=True, keep=True) is NOT enough on its own: retained
7.17.0 source shows strict checks whether files exist, while unreadable inputs
may warn/skip. Direct explicit per-object update is proposed to avoid treating
partial combination as all-nine success. No private SQL decoder or manually
manufactured coverage database. No dumps/loads of unknown bytes; their format
is distinct from data files and not a way to bypass source/tool qualification.

The report stage uses the pinned Coverage object/config and its supported
json_report, with no collection or tracing started by the aggregator. Binding
the explicitly populated destination without implicit other-data load, closing
all owned library connections, preserving primary cancellation/error and
warning policy need exact source review. On process control, required owned
cleanup only; no optional reporting, new input, next phase or unlink. Missing
termination or side effects retain UNKNOWN. No universal drain claim follows.

## Finite controls proposed within the existing cap, no execution grant

At the actual pinned coverage/process boundary require an intentionally executed
and unexecuted source statement, branch/context preservation, nine exact-role
inputs including a legitimate empty input and identical-byte distinct-role
inputs; no stale extra file contributes. Missing/wrong run or source/duplicate
role/reused PID/change or missing terminal/nonzero pytest/flush failure refuses.
Unreadable/corrupt/line-only branch mismatch and source/denominator drift refuse;
copy/source alias and unknown sidecar preserve original data and stop. Mutation
of one input after preflight must be detected. Ordinary library/report failures
retain raw failed evidence; cancellation starts no optional next input/report,
with owned connection cleanup evidence and no manufactured terminal. Verify
raw original hashes unchanged. No testing of transient-service/cgroup backends
or held herald supervisor, and no production child-env/executable bypass.

Exact control count/selector and whole import/copy/API/report/close/archive cost
must be frozen in the common budget before admission. This list is acceptance
direction, NOT extra control jobs or fit proof. If a faithful useful package
cannot fit, stop/report lead before compute rather than silently dropping
processes, hotspots, branches, corpus sizes or censored cells.
