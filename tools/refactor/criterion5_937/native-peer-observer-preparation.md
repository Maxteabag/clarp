# One-shot native socket observer — implementation preparation

`native_peer_observer.py` implements the narrow direction C accepted in
criterion5-937-abc501d9-readiness-client-design-C.md. Source only, UNEXECUTED;
not source-ready or integrated into a root, reader, scheduler or runner.

## Delegation and evidence scope

The admitted owner supplies the actual OWN-pin RuntimeClient class and private
client. The component checks exact class/bound-method identity and declared
prepared source filenames for _connect/_request/status_within. Filenames are
not loaded-code/source authentication; that remains the outer qualified owner.
No product module is imported or copied here. No RPC bytes, socket timeout,
protocol, endpoint, provider or native retry behavior is changed.

ONE public status_within call scopes the private instance's _connect binding.
Its original arguments are delegated once. The original returned socket is
used for a12-byte Linux native @iII SO_PEERCRED read and returned unchanged to
native _request. No second socket/RPC, duplication or socket proxy is created.
The one-shot guard does not wait to serialize native calls. Unexpected use is
sticky UNKNOWN and raises a separately labelled tool ownership refusal BEFORE
an additional socket/RPC. It is not an automatic retry or product finding; the
parent must stop/reconcile offered/completed/not-started/outstanding work.
Unexpected direct/native use while the binding is active likewise refuses
before allocating another socket. Do not blindly reuse an unowned client.

Ordinary metadata failure preserves the native call, result and primary error.
The returned object/result is never stored in receipts. Primitive peer/instance/
timing/absence/error-type fields only are retained. Constructor source/type
declarations and expected peer numbers are not Popen, namespace, path ownership
or source certificates. A CAPTURED socket observation is not full readiness.
Expected-instance comparison is explicit; the parent still needs actual live
PID/start/boot/source/socket/namespace brackets and stable native-instance joins.

## Ownership, control and restoration

If original _connect raises before returning, its existing native cleanup stays
native. Once it returns, a control exception preventing wrapper handoff closes
that exact returned socket ONCE, then propagates the original control object.
A close failure latches UNKNOWN; no raw-fd fallback/retry and no different socket
is closed. Observer-origin control is identified separately from an unclassified
native/public-call error; this component cannot label a product defect.

Delegation and assignment are inside the ownership handler. Before a returned
socket is actually bound locally, native/interpreter cleanup remains in force;
the connect-return-to-assignment gap is ALSO not certified. Never close/retry an
unknown object based on a missing local binding.

Wrapper-return intent is NOT atomic native-with ownership. This seam cannot
certify the interpreter gap or all-descriptor drain. Keep UNKNOWN/outer owned
process containment unless the actual supported interpreter lifecycle control
establishes the required behavior. No _request rewrite/proxy is used to heal it.

Finally covers installation itself, native success/error/control and metadata
updates. Restore the exact prior own attribute or delete an introduced one;
do not replace an originally inherited method with a captured bound object.
An unexpected replacement is not clobbered. Failed restoration means quarantine,
not client/process reuse. A pending control suppresses the optional end-clock
call. Cleanup cannot replace an existing primary; a new cleanup control with no
primary propagates. All fields/lifecycle claims still need finite fault proof.
