# Populated seed: literal path contract (source proposal, not qualified)

The common populated seed must be constructed at the SAME literal active
workspace used by every measured cell and its own-pin reference, for S and L.
The active path is selected once in the future immutable campaign manifest,
before generation/construction, not inferred from a returned row or moved main.
No exact path is allocated by this source. A and B source checkouts, bytecode
prefixes and per-attempt diagnostics remain separate from this active state root.

`seed_paths.py` reads the existing typed ALL-table snapshot. For each of the
three synthetic owners it checks the exact backend session, actual messages'
`source_file` (literal transcript path or the independently seeded
`client:synthetic`) and exactly one native checkpoint at that transcript path.
It records observed row counts without calling them allocations or capacities.
No raw value is rewritten, removed or masked. Other owners and ALL other raw
fields/tables remain the separate full-product oracle's responsibility.

The INITIAL constructor now produces this census from actual captured native
products. Closed-seed qualification repeats it against the closed capture,
compares it with the constructor receipt and retains the entire exact raw diff.
This is a new UNREVIEWED delta to c691/4f71, not old source approval or executed
native evidence. Receipt/hash/launch authenticity is still the outer owner's
responsibility. A forged JSON object is never a process or SQLite certificate.

Before a later operation starts, `require_same_workspace` rejects a different
initial/operation path, including aliases that look equivalent after resolution.
It performs no filesystem access or path resolution. It is NOT wired into a
complete root/reference coordinator yet. Caller adoption and an actual native
initial/closed/measured/reference control remain required before source-ready.

## What unchanged replay still needs

Exact native row equality, not parsing count, determines allocations. A inline
and B `_upsert_row` retain revisions/time for equal payload/trace/phase; a
source/seq-only move can still write a keyed edge with an OLD revision. This
contract prevents one declared source-path mismatch only. It does not establish
unchanged payload, origin, phase, client provenance, reply adoption or summaries.

The A inline turn-summary SELECT/order/summary fields and B `turn_stamp` must
be compared through their actual expressions. They order rows across sessions
by timestamp then seq, with no third tie-breaker. The recipe's 60-second requests
and +2-second replies are not alone a proof that the actual seeded/adopted rows
contain no timestamp/seq ties. Verify the raw trace membership, selected native
turn, outcome, tools/cells and last-summary row, not a globally equal stamp AST.

Even an unchanged row may be visited in a locked replay that records ancillary
helpers; full-parse reads still incur observer CPU/locks. Native batch commits
can depend on elapsed hold time as well as sequence, and checkpoints/heads,
restamps, deletes, retries and direct/startup/recovery actors need their own
actual count/epoch/key/cost bounds over repeated imports. No8192/512 fit or
36-allocation bound is claimed. This source adds no compact-recorder machinery.
