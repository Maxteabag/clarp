## Four proposed cases, one offered native status each

1. Successful native protocol exchange with real same-socket peer read, native
   result identity, explicit absent attestation and socket-only CAPTURED.
2. Observer metadata OSError with successful original native request/result:
   UNKNOWN, exact result identity, no observer close or replacement RPC.
3. Deliberately wrong expected peer PID: actual credentials stay untouched,
   native result is preserved and observation stays UNKNOWN.
4. Native unavailable response plus metadata OSError: the actual native decoder
   raises RuntimeUnavailable; its weak-referenced exception must be the exact
   selected exception, not an observer replacement. UNKNOWN remains non-green.

## Bounded owned fixture, archive and cleanup limits

Each case reserves a4s local socket/join horizon with1s reserved for cleanup;
server accept/receive/send share the earlier absolute I/O end instead of resetting
per-read timeouts. Native status retains its real0.5s deadline unchanged. Before
each next case the remaining inclusive setup allowance must cover that horizon.
This arithmetic is NOT a whole hard-end or fit certificate: imports/source
validation/hooks/serialization/fsync/fetch/archive and scheduler/kernel stalls
need the still-owed qualified outer supervision and accounting. Do not report
four cases as16s inclusive proof or expand the campaign/control budget.

The server owns one accepted connection and always closes it/sets completion.
The parent always attempts hook restoration, listener close and one bounded join.
Thread-alive/failed/unknown results preserve the endpoint and fail without the
next case, cleanup retry, alternate endpoint or DRAINED/all-descendant claim.
Original errors remain selected, cleanup errors retained as causes. Process
control triggers only required cleanup then propagation; no optional archive/
new probe is attempted after cancellation, so evidence/lifetime may be UNKNOWN.

For ordinary completion/failure, raw prefix/input and a preliminary case receipt
are archived before endpoint cleanup. An alive worker is DIAGNOSTIC_PREFIX_ONLY,
never complete history. Only a positively joined server, matching original socket
inode and already archived evidence permits unlinking that owned endpoint. A
separate terminal receipt follows. Preliminary success is not cleanup success or
a zero-exit proof. Any archive/identity/unlink failure stops, preserving artifacts.
