01 / Intent

A promise, not progress.

An unlit wire frame marks recorded intent. The small seal identifies the work. An empty frame does not claim anything has been completed.

Look for: dark panes, a dashed frame, one seal.

Only recorded running work flickers. Completed work settles and dims over time. Lantern size reflects a broad stage, not percentage complete, folder bytes or a tool-call score.

05 / What stayed grounded

More expression.
The same evidence discipline.

Where does the information come from?

Intent comes from recorded task plans. Activity is attributed by agent identity and overlap with a plan’s time window, not claimed as causal proof. Outcomes come from recorded artifacts. An artifact without a plan can appear with a hollow identity tag; a closed plan without an artifact stays unlit.

Do moving connections always mean a handoff?

No. Configured repository relationships stay structural. A push can animate delivery. An agent message referencing a plan pins that plan’s seal at a knot; a reference is not a transfer. Explicit transfer visuals require explicit transfer evidence. Stage two preserves these distinctions.

Did this change World or Agent cabinets?

The new lantern treatment is in Flow. The earlier World and Agent cabinets remain separate options. Future procedural additions receive the updated visual brief; the exact lantern silhouette and palette remain revisable design choices.

What is still imperfect?

Some Claude-backend observations lack a working directory, so those agents may remain in “Location unknown.” Crowded project regions show a limited number of lanterns with an overflow count. Research symbols can be dense close up. These are limits of this iteration, not proof of inactivity or missing work.

How was it checked?

The integrated version passed the Flow, mobile and real-history replay checks plus 15 focused JavaScript tests. Screenshots were opened and inspected. Integration corrected flicker based on recency, high-density zoom thresholds, and invented source dots when source counts were absent. The live service was stable with no restarts during deployment verification. This is browser verification, not a claim of physical-device Safari testing.
